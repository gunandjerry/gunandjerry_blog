이 튜토리얼에서는 기본적인 조명에 대해 다룰 것이다. 기본적인 Blinn-Phong 반사 모델과 정점당(Gouraud) 라이트, 픽셀당(Phong) 라이트에 대해 배워보겠다.
Blinn-Phong 반사 모델은 PBR 모델이 등장하기 이전까지 널리 쓰이던 모델로, 쉽고 간단하지만 그만큼 표현력에 한계가 명확하다. 최신 게임에서는 더이상 사용되지 않는다.

조명 이론

가장 먼저 반사 모델과 셰이딩 모델의 차이점에 대해 알아야 한다. ‘반사 모델’이란 표면에 부딪히는 모든 입사 광선들을 표면이 어떻게 반사하는지 계산하는 수학적 모델이다. 여기엔 광선의 방향, 세기, 표면의 법선벡터와 재질 등이 고려된다.

‘셰이딩 모델’은 반사된 표면이 어떻게(주로 어떤 색으로) 그려지는 지 결정하는 모델이다. 정점 별로 수행할 경우 색상은 각 정점에서 설정되고, 그 사이는 해당 폴리곤을 이루는 정점들의 보간으로 결정된다. 반면 픽셀별로 수행하는 경우 출력되는 각 픽셀마다 연산이 수행되어 폴리곤 당 3번씩 연산하는 정점단위보단 비용이 커도 훨씬 정교한 연산이 가능하다. 전자를 Gouraud 라이트, 후자를 Phong 라이트라고 부른다.

조명의 필수 부품

  1. 광원의 종류
    광원에는 여러 종류가 있다. 대표적인 것은 태양이 뜬 것 처럼 모든 월드 공간에 동일한 입사각, 세기의 빛을 가하는 Directional(Diffuse) Light / 전구처럼 특정 위치로부터 빛을 뿜어내는 Point Light / 특정 위치에서부터 특정한 영역에 대해서 원뿔 형태로 빛을 가하는 Spotlight 등이다.

  2. 광원의 강도와 색상
    각 광원은 색상과 강도를 가진다. 혹은 강도와 색상을 결합하여 사용하는 경우도 있다.

표면

빛이 표면에 닿으면 두 가지 방식으로 반사된다.

  1. 확산(Diffuse) 반사 / 난반사
    확산 반사는 물체 표면에 입사한 빛이 입자들과 상호작용하며 산란과 투과를 되풀이하며 이리저리 튕겨져 나오는 것을 말하고(위 그림의 파란 화살표들), 난반사는 표면이 울퉁불퉁한 물체에 닿았을 때 빛이 사방으로 흩어지며 반사되는 것을 말한다. 분명히 구분되는 개념이지만 여기서는 대충 한 방향에서 빛이 들어와도 전 방향으로 산란되어 반사되는 의미로 동일하다고 생각하자.

  2. 정(Specular) 반사
    확산반사/난반사와 달리 광선의 일부 색상은 물체에 흡수되고, 나머지는 입사각에 대한 반사각을 만들어 반사되는 것. 표면이 매끄러울 수록 반사각의 호 형태 범위가 좁아지고, 반대로 표면이 거칠 수록 호 형태 범위가 넓어진다.
    확산 반사는 전방위로 튀니까 상관 없었지만, 정반사에 의해 맺히는 상은 보는 시점에 따라 어떻게 보이는지가 달라진다는 것을 주의하자. 예컨대 정반사에 의해 반사된 빛을 볼 수 있는 사람은 반사각을 이루는 호 영역 안에 있는 사람 뿐이며, 반사각과 시선의 각도가 좁을 수록 반사된 빛을 더 강하게 느낄 수 있다. 또 광원이 물체에 반사되어 생기는 둥근 모양의 하이라이트를 볼 수 있는데, 이를 Specular Highlight라고 한다.

우리가 여기서 다룰 빛과 반사의 개념들은 모두 ‘Local Light’이다. 로컬 조명이란 빛의 2차 반사, 장애물 등을 고려하지 않고 각 물체들과 광원만을 독립적으로 계산하는 단순한 방식을 말한다.
따라서 Local Light 환경에선 자연스러움을 추가하기 위해 한 가지 빛을 더 추가한다.

  1. 주변(Ambient) 반사
    현실에서 물체는 주 광원의 빛만 받는 것이 아니라 자신을 둘러싼 주변의 다른 물체들로부터 반사된 빛에 의해서도 비춰진다. 하지만 이를 현실적으로 구현하는 것은 매우 복잡하기 때문에, 우린 단순히 모든 물체에 동일한 강도의 주변광 반사를 추가하여 이를 ‘흉내내는’ 방식을 취할 것이다.

모든 표면은 어떠한 재질로 이루어지고, 각 재질은 빛을 다르게 반사한다. 따라서 재질 매개변수를 두고 다양한 반사의 강도를 제어할 필요가 있다. 여기서는 단순히 4개의 float 변수로 이를 표현해보겠다. 보다 정교하게 하고 싶다면 재질의 색상 값도 고려하면 좋다.

  1. mAmbient : 주변광을 반사시키는 강도
  2. mSpecular : 정반사광을 반사시키는 강도
  3. mDiffuse : 확산반사광을 반사시키는 강도
  4. mShiness : 표면의 광택도. 이 놈은 Specular Highlight의 밝기와 범위를 제어하는데 사용한다.

필요한 벡터들

우리의 단순한 조명 모델을 구현하기 위해 알아야하는 벡터들은 다음과 같다.

  1. Directional Light의 방향의 반대 벡터 L
  2. 표면의 법선 벡터 N
  3. Directional Light가 표면을 치고 정반사되어 나갈 때의 반사벡터 R
  4. 보는 시점의 위치 벡터 V
    조명 연산에는 내적을 사용하기 때문에, 모든 벡터는 단위벡터이면서 정점(또는 픽셀)의 위치로부터 출발해야 한다.

이론적 구성

난반사 ~ 램버트 법칙

램버트 법칙은 확산 반사되는 빛의 강도가 광선의 방향과 법선 벡터가 이루는 각도의 코사인에 비례한다고 설명한다. 우리는 모든 벡터를 단위벡터이고 같은 출발점을 가진 벡터로 관리하고 있으므로, 이는 N 벡터와 L 벡터의 내적으로 간단하게 구할 수 있다.

Note

내적의 결과는 음수가 나올 수 있다. 빛에 음수는 없으니 saturate() 함수를 사용해 0~1 사이 값으로 clamping해야 한다.

앞서 물체의 재질을 표현하기 위해 난반사 강도 매개변수 mDiffuse를 두었으므로, 이를 곱하면 최종적인 난반사 강도가 된다.

최종 난반사 강도 = mDiffuse 광원의 세기

정반사

정반사는 시야와 반사벡터에 따라 달라진다. 이 역시 단순히 R 벡터와 V 벡터의 내적으로 간단하게 구할 수 있다. 또 표면이 얼마나 매끄러운 지도 고려해야 하는데, 표면이 매끄러울 수록 반사광의 호는 좁아지고 반사되는 빛의 세기는 강해지는데, 이는 Specular Highlight의 크기와 강도를 조절하여 표현한다.
이를 위해 R, V의 내적이 충분히 클 때만(즉, 두 벡터의 각도가 좁을 때만) Specular Highlight가 보이도록 해야 한다. 여기선 HLSL의 exp(x)함수(, 자연상수(약 2.718)의 x제곱을 반환) 함수를 사용하면 좋을 것이다.

최종 정반사 강도 = mSpecular exp(, mShiness) 광원의 세기

감쇠율 추가

일반적으로 Specular Highlight는 Directional Light에 의해서 생기는데, Directional Light는 거리가 무한인 가상의 광원이기 때문에, 거리가 멀어져도 Specular Highlight의 크기는 커져도 세기는 유지되는 문제가 있다. 현실성을 부여하려면 거리가 멀어질 수록 눈에 들어오는 빛의 양이 줄어들기 때문에 Specular Highlight의 세기도 낮아져야 한다.
시선 벡터의 크기를 구해 감쇠율에 곱하는 방식으로 간단하게 감쇠율 매개변수를 계산할 수 있다. 거리의 제곱을 사용하면 조금 더 자연스럽다.

감쇠율 매개변수 = 1.0 / (1.0 + attenuation_strength length length);

주변 반사

주변 반사는 단순히 동일한 반사 강도를 입히는 것에 불과하므로 매우 간단하게 구할 수 있다.

최종 주변반사 강도 = mAmbient * 광원의 세기

최종 광도

최종 광도는 이들을 모두 더하면 된다.

Blinn-Phong 라이트

위에서 배운 모델은 가장 기본적인 Phong 반사 모델이다. 이 모델은 단순한 조명 모델을 잘 구현해내지만, 과거 컴퓨터의 성능이 떨어지던 시절에는 들어오는 광선의 반사각을 구하는 연산조차 부담이 커서 쓰기 힘들었다.
그래서 등장한 것이 Blinn-Phong 라이트로, 기본적으로 위 반사 모델과 동일하지만 반사 벡터를 구하는 대신 광선과 시선 벡터의 ‘반각’을 사용하는 방법을 사용한다.

반각 벡터 H = ||L + V||

따라서 앞서 구했던 정반사 강도 공식은 다음과 같이 수정된다.

블린 퐁 라이트의 정반사 강도 = mSpecular exp(, mShiness) 광원의 세기

주의할 점은 블린 퐁 라이트를 사용할 경우 표면의 매끈한 정도를 나타나는 mShiness의 값을 대체로 더 높게 설정해야 한다는 것이다. 왜냐하면 반각벡터를 사용하는 방식이 실제 반사 벡터를 구해 법선과 내적하는 것보다 값이 상당히 작게 나오기 때문이다.

HLSL로 구현하기

이제 실제 코드로 이를 구현해보자.

HLSL 구조체

Texture2D shaderTexture : register(t0);
SamplerState sampleType : register(s0);

// Vertex Shader Stage Set
cbuffer ConstantBuffer : register(b0)
{
    matrix worldMat;
    matrix viewMat;
    matrix projMat;
    float3 camPos;
};

// Pixel Shader Stage Set
struct Light
{
    float4 diffuseLightColor;
    float3 diffuseLightDirection;
    float diffuseLightIntensity;
    float4 ambientLightColor;
    float4 specularLightColor;
    float ambientLightIntensity;
    float specularLightIntensity;
    float specularAttenuation;
};
cbuffer LightBuffer : register(b1)
{
    Light cbLight;
};
struct Material
{
    float4 ambientReflectColor;
    float4 diffuseReflectColor;
    float4 specularReflectColor;
    float ambientReflectStrength;
    float diffuseReflectStrength;
    float specularReflectStrength;
    float shiness;
};
cbuffer MaterialBuffer : register(b2)
{
    Material cbMaterial;
};

// Parameter structures
struct VS_INPUT
{
    float4 pos : SV_POSITION;
    float4 color : COLOR0;
    float3 normal : NORMAL;
    float2 uv : TEXCOORD0;
};

struct PS_INPUT
{
    float4 pos : SV_POSITION;
    float4 worldPos : POSITION;
    float4 color : COLOR0;
    float3 normal : NORMAL;
    float2 uv : TEXCOORD0;
    
    float3 V : TEXCOORD1; // 얘는 VS에 Set하는 ConstantBuffer(b0) 안에 있는 CamPos를 써야 하므로 VS에서 만들어서 PS로 전달
    float V_length : TEXCOORD2;
    // 얘네 둘은 라이트 정보가 있어야 하므로 PS 안에서 만들어야 함.
    //float3 L : TEXCOORD3;
    //float3 R : TEXCOORD4;
};

Vertex Shader

#include <shared.fxh>

PS_INPUT main(VS_INPUT input)
{
    PS_INPUT output;
    input.pos.w = 1.0f;
    
    output.worldPos = mul(input.pos, worldMat);
    output.pos = mul(output.worldPos, viewMat);
    output.pos = mul(output.pos, projMat);
    
    output.color = input.color;
    output.uv = input.uv;
    
    output.normal = normalize(mul(input.normal, (float3x3) worldMat));
    output.V = normalize(camPos - (float3) output.worldPos);
    output.V_length = length(camPos - (float3) output.worldPos); // 이유를 모르겠으나 이 값이 상당히 크게 나온다. 대체 왜?
    
    return output;
}

Pixel Shader

#include <shared.fxh>

float4 main(PS_INPUT input) : SV_TARGET
{
		// VS에서 이미 정규화를 해서 넣었으나, Pixel Shader 입장에선 그 사실을 알 수 없으므로, 다시 정규화를 해주는 습관을 들이는 것이 좋다.
    input.normal = normalize(input.normal);
    
    float3 V = normalize(input.V); // 정점으로부터 카메라로 향하는 벡터
    float3 L = -normalize(cbLight.diffuseLightDirection); // Directional Light 벡터 반전(내적을 위해)
    float3 R = normalize(reflect(cbLight.diffuseLightDirection, input.normal)); // 반사각 벡터 (들어가는 입사각에 대해 표면에서 나오는 반사각을 반환하므로 부호를 반전하면 안 됨)
    
    float4 base_color = shaderTexture.Sample(sampleType, input.uv) * input.color;
    
    float NdotL = dot(input.normal, L);
    float RdotV = max(0.0f, dot(R, V));
    
    float diffuse_strength = cbMaterial.diffuseReflectStrength * saturate(NdotL) * cbLight.diffuseLightIntensity;
    float specular_strength = cbMaterial.specularReflectStrength * pow(saturate(RdotV), cbMaterial.shiness) * cbLight.specularLightIntensity;
    float ambient_strength = cbMaterial.ambientReflectStrength * cbLight.ambientLightIntensity;
    
    // optional, specular attenuation
    float length_modified = input.V_length * 0.1f; // length값이 왠진 모르겠는데 너무 높게 나옴
    float attenuation_strength_modified = cbLight.specularAttenuation * 0.001f;
    float attenuation = 1.0f / (1.0f + attenuation_strength_modified * pow(length_modified, 2));
    speuclar_strength *= attenuation;
    
    float4 diffuse_color = cbMaterial.diffuseReflectColor * cbLight.diffuseLightColor * diffuse_strength;
    float4 specular_color = cbMaterial.specularReflectColor * cbLight.specularLightColor * specular_strength;
    float4 ambient_color = cbMaterial.ambientReflectColor * cbLight.ambientLightColor * ambient_strength;
    
    float4 final_color = base_color * (diffuse_color + specular_color + ambient_color); // 단순히 더하는 식으로 구한다.
    final_color.a = base_color.a;
    
    return final_color;
}
