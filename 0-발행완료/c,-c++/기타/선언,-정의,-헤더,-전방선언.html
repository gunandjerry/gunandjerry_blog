선언, 정의, 헤더, 전방선언

선언 (Declaration)

컴파일러에게 식별자(타입이나 함수의 이름)를 알리는 행위. 그러한 역할을 하는 명령문(Statement).

선언은 단순히 컴파일러에게 "여러 목적 파일들 중 어딘가에 이러한 이름을 가진 타입 또는 함수의 정의가 있다"는 사실을 알리는 것이다.
따라서 선언은 여러 번 중복되어도 상관 없다. (같은 목적 파일 안에서 중복되어도 상관 없다)

정의부에선 선언만 있고 정의가 없는 타입이나 함수에 대해서도 포인터를 선언하거나 호출할 수 있다. '어딘가에 존재한다는 사실'만을 알면 그 위치를 담기 위한 포인터 변수를 마련하거나, 어딘가에 존재할 함수의 위치를 주소로 찾아서 호출할 수 있기 때문이다.
그리고 링커(Linker)가 실제 함수의 정의부를 찾아서 연결해주는 작업을 수행하는 녀석이다.

선언되지 않은 식별자를 사용하면 '컴파일' 단계에서 알 수 없는 식별자 에러가 발생한다.

정의 (Definition)

실제 로직(프로세스가 실행될 때, 실제로 메모리에 적재되어 수행되는 부분)을 작성하는 것. 식별자의 실체를 만드는 것.
모든 정의는 선언이다. 즉 정의를 하면서 동시에 선언을 하게 된다.

선언이 있는데 어디에도 정의가 없다면 '링크' 단계에서 존재하지 않는 정의 에러가 발생한다.

헤더 파일

흔히 발생하는 착각 중 하나가 "선언은 헤더 파일에서, 정의는 소스 파일에서" 한다는 것. 이는 완벽한 착각이다.

헤더 파일은 include 예약어를 통해 '복사되는' 텍스트 덩어리이며, 소스 파일(.c, .cpp)은 목적 파일로 컴파일되는 단위이다.

즉 선언이냐, 정의냐로 구분되는 단위가 아니다. 실제로 헤더 파일에 정의를 하고 복사하여 사용해도 된다. 물론 그게 일반 함수의 정의라면 한 곳에서만 복사할 수 있으므로 헤더 파일로 만드는 의미는 없겠지만.

그리고 템플릿 함수와 같은 인라인 함수는 컴파일러가 정의가 중복으로 존재하더라도 알아서 하나로 취급해주기 때문에 헤더에 정의를 두고 여러 곳에 복사해도 된다.

C++의 클래스(구조체)는 더욱 특별한데, 클래스의 구조(멤버 변수와 멤버 함수)를 작성하는 행동은 분명히 '정의'에 해당하지만, 이를 특별히 클래스의 설계도로 취급하여 내용이 토씨 하나 안 틀리고 똑같다면 여러 소스 파일에 중복으로 정의되어도 괜찮다는 ODR(One definition rule)의 예외가 적용된다.

그래서 보통 클래스의 정의는 헤더 파일에서 이루어지는 것.

전방선언 (Forward Declaration)

타입의 서명만 미리 알리는 선언. 정의가 없는 선언의 한 형태.
C 시절에 구조체에 대해서 쓰이던 문법이지만 C++에서도 여전히 쓰인다. C++의 클래스(구조체)는 ODR의 예외에 따라 정의가 중복으로 존재할 수는 있지만, 상호참조의 문제는 여전히 존재하기 때문이다. (+ 정의는 컴파일에 포함되므로 중복된 정의는 그만큼 비용이 되기도 한다.)

다음은 전형적인 순환 참조의 오류이다.

#include "B.h"

class A{ B* MyB; };

#include "A.h"

class B{ A* MyA; };

하나의 헤더 파일을 복사하면 A -> B -> A -> B 순으로 무한히 복사하게 된다. 헤더 가드로 중복 복사를 막을 순 있지만 순환 참조 오류의 근본적인 해결책이 될 순 없다.

Note

보통 구분없이 쓰이긴 하지만, 전방선언은 타입 서명을 선언하는 것을 말한다. 함수의 서명을 선언하는 건 함수 원형(Function prototype)이라고 부르는 게 맞다.

여담

C++에서 클래스(구조체)의 구조를 작성하는 건 '클래스의 정의'에 해당하지만, 이 때 데이터 멤버와 멤버 함수들의 서명을 적는 건 그 각각의 변수와 함수들에 대한 '선언'에 해당한다.

클래스의 정의는 어디까지나 설계도 코드를 작성하는 것임을 명심해야 한다. 설계도는 설계도를 저장하기 위한 메모리만을 요구할 뿐 설계도가 있다고 그 자체로 값을 담을 수 있는 변수나 호출할 수 있는 함수가 생성되는 건 아니다.

이 사실을 모르고 있으면 어째서 static 멤버 변수를 클래스 안에 선언할 때 사용하려는 소스 파일 안에서 '다시 선언'을 해야 하느냐는 의문이 들 수도 있다.
static 멤버 변수나 static 함수는 위치만 클래스 안에 있어 스코프가 제한될 뿐 어디까지나 전역 변수, 전역 함수와 같이 데이터 영역에 생성되는 것으로 실제로 그 클래스의 멤버로서 설계도 안에 포함되는 것은 아니다.
따라서 클래스의 설계도에선 '이러한 static 변수를 이 안에서만 사용하게 하겠다'고 선언하는 것일 뿐 실제로 static 변수를 정의하는 건 소스 파일 안에서 수행되는 것이다. (즉, 다시 '선언'하는 게 아니라 '정의'를 거기서 하는 거다)
