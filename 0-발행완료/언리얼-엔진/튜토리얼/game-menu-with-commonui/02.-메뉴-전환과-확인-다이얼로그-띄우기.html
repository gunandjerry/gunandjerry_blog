2. 메뉴 전환과 확인 다이얼로그 띄우기

메뉴 전환하기

버튼을 눌렀을 때 다른 메뉴 화면이 나타나게 해보자.

메뉴 버튼들이 담긴 VerticalBox를 Variable로 설정하고, Common Animated Switcher로 감싼다. UMG의 Switcher 위젯과 동일한 역할을 수행하지만, 'Animated'란 명칭이 들어간 것처럼 전환 효과를 쉽게 만들 수 있다.

Details의 Transition 섹션에서 전환 효과를 설정할 수 있다.

추가한 스위처 밑에 VB_MainMenu를 복사하여 예시로 Settings 메뉴를 만들어보았다.

이제 버튼을 눌렀을 때 스위처가 전환되게 하자. 일단 각 위젯들의 이름을 정리하고 Variable 속성을 켜주었다.

이후 Settings 버튼과 Settings_Back 버튼의 OnClicked 이벤트에서 스위처의 액티브 위젯을 전환한다.

설정창의 모든 하위 메뉴마다 같은 동작을 반복해야 하므로, 함수로 만드는 것이 좋다.

다이얼로그 확인창 띄우기

섹션 완성 화면 미리보기

이번엔 Quit 버튼을 눌렀을 때 '정말 나가겠느냐'는 확인 다이얼로그 창을 띄워보자.

다이얼로그 창 자체는 범용으로 재사용할 것을 전제로 설계한다. UUserWidget WBP를 새로 만들고 이름은 S01_WBP_ConfirmationDialog으로 하자.
하이어라키는 대충 아래와 같다.

루트 엘리먼트는 백그라운드 블러로 이 위젯이 뷰포트에 바로 추가되면 전체 뷰포트에 블러를 입히게 된다. 블러 강도는 2.0으로 했다.
블러의 Visibility는 Non Hitable이 아니라 Visible로 설정하여 뒤에 있는 다른 메뉴 버튼이 눌리지 않도록 한다.

그 밑에 CommonBorder를 두었다. 다이얼로그 창의 영역을 그리는 역할을 할 것이며, 기존 UMG Border와의 차이는 CommonBorderStyle을 지정할 수 있다는 것 말고는 없다.

CommonBorderStyle은 지금까지 CommonUI 위젯의 스타일 객체를 만들어 왔듯이 똑같이 만들어서 끼우면 된다.

그 밑에 VerticalBox를 두어 메세지와 버튼을 세로로 배치한다. 버튼은 HorizontalBox에 Yes 버튼과 No 버튼을 넣었다.

UI 레이아웃 조절하기

보기 좋은 다이얼로그 창을 만들어보자. Common Border의 Content - Padding 또는 Vertical Box의 Border Slot의 Padding을 넉넉하게 넣는다. (동일한 변수다)
다이얼로그 메세지의 경우 Vertical Box Slot의 Padding Bottom을 주어 버튼과 적절히 떨어지게 하고,
Horizontal Box에 담긴 두 버튼은 가로 세로 중앙 정렬한 뒤 Size를 Fill(1.0)로 설정하여 동일한 영역을 차지하면서 적당히 떨어지도록 한다.

다이얼로그 창과 상호작용하기

지금 만든 다이얼로그 창은 범용적으로 사용하기 위해 만들었다. 또 다이얼로그를 생성하는 주체는 상위의 메뉴 위젯으로 다이얼로그와 상호작용한 결과 동작해야 하는 로직은 상위의 메뉴 위젯을 통해야 한다.

따라서 상호작용의 결과 동작하는 로직은 다이얼로그 자체에 내장하지 않고 Event Dispatch(C++로 치면 Delegate)로 외부에서 등록한 로직을 콜백만 해주도록 한다.

다이얼로그 위젯에 다음과 같이 Yes 또는 No 버튼 중 무엇이 눌렸는지 알리는 Event Dispatch를 추가한다.

그리고 Yes/No 버튼이 눌렸을 때 콜백한다. Yes든 No든 다이얼로그 위젯은 공통적으로 제거되므로 제거되는 것만 여기서 해준다.

이제 메인 메뉴 위젯에서 Quit 버튼을 눌렀을 때 다이얼로그를 생성하고, Yes를 누르면 게임을 꺼지게 해보자.

먼저 다른 메뉴 버튼에서도 다이얼로그를 띄울 일이 많을 것 같으니 다이얼로그를 생성하고 띄우는 동작을 함수로 빼보자.

Note

위 함수에 Pure 속성을 체크하지 않도록 주의. Pure 함수는 핀이 연결되어 사용될 때마다 호출되므로 위젯을 여러 개 만들게 된다. 물론 캐싱용 변수를 만들고 이미 존재할 때 반환만 하게 하면 상관 없다.

부드러운 다이얼로그

다이얼로그 위젯이 나타나고 사라질 때 부드러운 페이드 인 아웃 효과만 넣어도 훨씬 보기 좋아진다.

Fade In은 Pre Construct에서, Out은 Input Dispatch 콜백 이후에 재생하면 된다. Fade Out은 Fade In 애니메이션을 Reverse로 재생했으며, 애니메이션의 End Time만큼 지연 후에 위젯을 제거한다.
