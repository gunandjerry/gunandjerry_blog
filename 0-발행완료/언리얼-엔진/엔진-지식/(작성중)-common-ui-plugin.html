(작성중) Common UI Plugin

Note

Common UI는 기존 UMG의 대체 시스템이 아니라 복잡한 UI 레이아웃을 가진 게임에서 쓸 만한 확장에 가깝다.
늘 필요한 것도 아니고 Common UI가 규정하는 사용법을 익히기 위해 시간을 들여야 하므로 UI가 간단하고 크로스 플랫폼에 신경을 쓸 필요가 딱히 없다면 사용하지 않아도 된다.
혹은, UI Navigation 3.0 처럼 다른 UMG의 확장 플러그인을 고려해봐도 된다: https://www.fab.com/listings/a91f6e67-5c2d-46ef-926d-00a35525579c

이거 설명 언리얼 4 기준인 거 같은데?
언리얼 5 Common UI 플러그인에 Layer에 위젯 Push하고 이런 노드나 설정 없음.
모달 UI는 심지어 CommonActivatableWidget에 IsModal 체크박스로 설정함.
레이어 개념 없애버린 거 아닌가?

Common UI

개요

크로스 플랫폼을 위한 UI 시스템. 포트나이트, Lyra Starter Game이 이걸 사용한다.
기존 UMG UI와 비교해서 다음과 같은 편의 기능들을 제공한다.

  • Enhanced Input과 연동해 UI에서 직접 Input Action을 바인딩하여 플레이어와 독립적인 키 바인딩이 가능하다. (주로 팝업 닫기 등 UI가 떠있을 때만 후킹되어야 하는 키 입력에 대해 처리할 때 쓰인다)
  • 플랫폼에 따라 버튼 힌트 텍스트나 이미지를 바꿔 끼우는 등 크로스 플랫폼을 위한 동작들을 쉽게 편집할 수 있다.
  • (특히 콘솔에서 중요한) 포커싱 이동 순서를 쉽게 관리할 수 있게 해준다.
  • 확인/취소/뒤로가기 등의 공통 조작을 범용으로 쓸 수 있게 해준다.
  • UI 위젯들을 스택 구조로 관리하여 뒤로가기 등의 동작을 쉽게 처리할 수 있다.

구조

Common Input

여러 입력 장치를 통합적으로 관리하기 위한 입력 추상화 시스템.
단적인 예시를 들자면 UI 팝업을 닫는 키가 키보드로는 Enter, 게임 패드로는 B, 모바일로는 버튼 터치라고 할 때, Common Input은 현재 플레이어의 입력장치를 감지해서 적절한 키

Common UI 위젯들

설정을 바탕으로 동작하는 Common UI에서 사용하는 위젯들. 각각 동작하는 방식과 사용하는 의도가 다르므로 쓰면서 배워야 한다.

사용법

플러그인 활성화

Common UI Plugin을 활성화한다.

Common Input 설정

입력 이벤트 라우팅

먼저 입력 라우팅(키 입력 신호를 전달)을 활성화해야 한다.
Edit - Project Settings - Engine - General Settings - Game Viewport Client Class를
CommonGameViewportClient로 바꿔주자.

이 뷰포트 클라이언트 클래스는 키 입력 신호를 Common Input의 '루트'에게 전달한다.

Common Input Action 정의

Common Input을 위한 Input Action 테이블이 필요하다.
Common Input의 기본적인 아이디어는 Enhanced Input System을 사용하는 입력은 플레이어의 조작을 위해, Common Input을 사용하는 입력은 UI 조작을 위해 사용하는 것이다.
이를 통해 입력 관리를 분리하고, 모든 UI를 범용적인 방법으로 관리할 수 있게 한다.

새 에셋 - Miscellaneous - CommonUI InputActionDataTable을 생성한다.

각 로우가 범용적인 기능을 담당할 UI 인풋 액션이 된다. 필수는 UI와 상호작용하는 '클릭'과 UI를 닫거나 이전 상태로 되돌리는 '뒤로가기' 동작이다.
이 두 동작은 특별히 'Default Click Action'과 'Default Back Action'이라고 모든 Common UI 위젯에서 범용적으로 사용되도록 만들어져 있다 (이후 설명하겠지만, CommonButtonBase 등 여러 Common UI 위젯에서 사용하게 된다)

여기서는 'Confirm'과 'Back'이라는 이름으로 만들어보겠다.

기본적으로 키보드 입력, 게임패드 입력(종류에 따른 오버라이드 가능), 터치 입력의 키 바인딩이 따로 존재한다.
위 이미지에선 Confirm 액션을 트리거하는 키가 키보드에선 Enter, 패드에선 Face Button Bottom (주로 A 버튼)으로 설정했다.

이제 두 액션을 기본 클릭과 기본 뒤로가기 액션에 바인딩해보자.
CommonUIInputData를 상속하는 블루프린트 에셋을 생성하고 아래와 같이 작성한 Common Input DT의 두 인풋 액션을 맵핑해준다.

이후 Project Settings - Game - Common Input Settings - Input Data에 해당 블루프린트를 등록한다.

컨트롤러 데이터 설정

컨트롤러 데이터는 인식된 입력장치를 관리하는 주체이다. 컨트롤러 데이터가 존재하는 입력장치에 대해 Common UI는 자동으로 입력장치를 감지하여 입력장치에 맞는 키 입력을 처리하고 키 힌트 등을 출력한다.

CommonInputBaseControllerData를 상속한 BP 에셋을 생성한다. 여기선 키보드+마우스와 게임패드 두 가지 컨트롤러를 사용할 수 있게 두 가지를 만들어보자.

BP를 열고 Input Type을 각각 알맞은 타입으로 지정한다.
그 밑의 Input Brush Data Map에서 각 키의 힌트 아이콘을 등록할 수 있다. 항목을 추가하고 키를 고른 뒤 그 키에 해당하는 키 아이콘 이미지를 등록하면 된다.

Note

Gamepad 타입의 경우 게임패드 기종마다 각각 관리해줄 게 아니라면, Gamepad Name 항목은 범용값인 Generic으로 둬야 한다. 다른 값을 입력하면 게임패드 이름으로 컨트롤러 데이터를 찾기 때문에 정상작동하지 않을 수 있다.

구분을 위해 키보드 마우스 입력장치일 땐 Enter 키의 아이콘으론 초록 사람 이미지를 써보자.

이후 Project Settings - Game - Common Input Settings - Platform Input 아래에 이 게임이 돌아갈 수 있는 모든 플랫폼에 우리가 만든 컨트롤러 데이터를 바인딩해줘야 한다.

여기선 Windows 플랫폼에만 바인딩해보았다.

이제 정상적으로 작동하는지 확인해보기 위해 샘플 키 힌트 아이콘을 띄워보자. 대충 WBP를 만들고 그 안에 Common Action Widget 위젯을 추가한다. 플랫폼, 입력장치별로 적절한 키 아이콘을 띄워주는 단순한 위젯이다.

위와 같이 Input Actions에 원하는 Common Input Action을 넣으면 된다.
이제 유저 위젯을 뷰포트에 부착해보면,

  1. 현재 Windows OS이므로
  2. Common Input Settings의 Windows 플랫폼 인풋에 바인딩된 Controller Data 중에
  3. 현재 키보드 마우스를 사용하므로 Input Type이 Mouse and Keyboard인 Controller Data를 고르고
  4. DT_UIActions의 Confirm 액션은 키마 입력장치일 땐 'Enter' 키에 해당하며
  5. 3번에서 찾은 Controller Data에는 'Enter' 키에 초록 사람 아이콘을 매핑해놨으므로

이렇게 해당하는 아이콘이 그려지게 된다.

Common UI Stack (Menu Stack)

본격적으로 Common UI 위젯에 대해 배우기 전에, Common UI의 UI 스택에 대해 먼저 배워야 한다.
Common UI의 핵심은 UI들을 스택에 쌓고 빼가며 관리하는 것이다. 키 입력 이벤트는 스택의 최상위에 있는 UI로 라우팅되어 해당 UI가 독점하여 처리하게 된다.

Common UI에는 여러 Layer가 있고 각각의 Layer마다 스택을 별도로 관리한다.

  • Game Layer : HUD 같은 인게임 UI들이 쌓이는 레이어. 플레이어 조작의 반응성이 아예 없거나 단순하다.
  • Menu Layer : 게임 메뉴나 플레이어와 적극적으로 상호작용하는 인벤토리 등의 UI들이 여기에 해당한다.
  • Modal Layer : 현재 행동의 확인창, 경고창처럼 반드시 플레이어의 입력을 소비해야만 하는 최상위 팝업 성격의 UI들이 여기에 해당된다.

기본적으로 우선순위는 Game Layer < Menu Layer < Modal Layer 순으로 크다.
예컨대 플레이어의 HUD는 따로 키 입력을 받지 않으며(Game Layer), 인벤토리 창을 열면 인벤토리 UI가 뜨면서 플레이어의 입력을 라우팅해가고(Menu Layer), 아이템을 버리는 행동을 할 때 확인 창을 띄워서 플레이어가 예 또는 아니오를 누를 때까지 모든 키 입력을 라우팅하며 대기(Modal Layer)하는 식이다.

작성중

Common UI Widget

CommonActivatableWidget

활성화되고(Activate) 비활성화될 수(Deactivate) 있는 메뉴 단위의 UI.
Common UI의 베이스 위젯으로 UUserWidget을 대체한다.

Common UI가 관리하는 UI 스택 위에서 생성되어 '활성화' 됨으로써 현재 플레이어가 제어하게 되는 최상위 UI로 사용되는 것이 핵심이다.

기존의 UUserWidget은 뷰포트에 부착하고(Add to Viewport), 부착된 대상으로부터 제거(Remove from Parent)하는 동작만 지원했다.
이렇다보니 메뉴가 여러 개 겹칠 때 처리하기 애매해지거나, 뒤로가기를 지원하려면 따로 기록을 해야한다거나, UI를 켤 때마다 입력 모드를 바꾸고 포커스를 일일히 지정해야 한다거나 하는 문제들이 많았다.

그래서 CommonActivatableWidget은 다음과 같은 기능을 제공한다.

  1. Common UI 스택과 연동하여 뒤로가기를 지원한다. 예컨대, ESC(메뉴 오픈) -> 게임 설정 -> 그래픽 설정 -> (여기서 뭔가 바꾸고 뒤로가기) -> 게임 설정 -> 게임메뉴로 왔다갔다 하는게 기본으로 가능하다.
    더 구체적으론 CommonActivatableWidget은 생성되

이렇게 메뉴 스택을 사용함으로써 메뉴 열기 -> 게임 옵션 -> 그래픽 옵션에서 그래픽 설정을 건든 후, 뒤로가기를 하면서 역으로 게임 옵션 -> 메뉴 순으로 이동하는게 가능해진다.

  1. 위에서 말한 Common UI 스택과 연동. Default Back Action이 발생하면 위젯을 제거하며 메뉴 스택에서 제거함으로써 이전의 메뉴로 돌아갈 수 있다.
  2. 위젯을 생성한 후 'Activate'
  3. OnActivated, OnDeactivated 라는 화면에 '보이기 시작할 때'와 '사라질 때' 호출되는 이벤트를 제공하여 위젯을 열고 닫을 때 동작해야 하는 로직들을 위젯 각각에서 독립적으로 처리할 수 있게 한다. (위젯 객체가 인스턴싱되고 제거될 때 호출되는 Construct/Destruct와 다르니 주의)
