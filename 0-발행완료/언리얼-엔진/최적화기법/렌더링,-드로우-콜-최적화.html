렌더링, 드로우 콜 최적화

Draw Call

CPU가 GPU에게 현재 파이프라인 상태를 캡쳐하여 그리라고 명령하는 것.
DX11을 기준으로 각 파이프라인의 상태를 설정하고(정점 버퍼, 셰이더 코드, 텍스쳐 바인딩 등) DrawIndexed 같은 Draw류 명령을 내리는 순간 발생한다.

GPU는 자신의 명령 큐에 드로우 콜이 들어오면 파이프라인 상태를 전환하고 일정한 절차에 따라 픽셀을 그려내게 된다.

이 과정에서 CPU <-> GPU 간의 통신이 필요한데, 통신 비용 자체도 크거니와 드로우 콜을 발생시키는 것 자체가 CPU와 GPU의 동기화 포인트가 되는 것이 일반적이므로 병목이 발생하기 쉽다.

언리얼에서

언리얼에선 렌더링을 담당하는 RHI 스레드가 게임 스레드와 분리되어 있다. 그렇다고 오해하면 안 되는 게, 렌더링 스레드는 보통 1프레임 전의 게임 상태를 게임 스레드가 동작하는 동시에 그려낼 뿐, 두 스레드의 초당 틱 수는 같다고 보아야 한다.

따라서 렌더링 비용이 너무 커서 게임 스레드가 Tick을 다 처리했는데도 렌더링이 끝나지 않으면 게임 스레드도 WaitForTicks 유휴 시간을 가지며 병목 상태가 된다.

그리는 작업과 그리는 비용 자체를 줄이기

가장 흔하고 확실한 최적화 방법이다.

  • 텍스쳐의 크기를 줄여 픽셀 셰이더가 처리할 데이터 양을 줄임으로써 비용을 줄인다.
  • Occlusion Culling, Distance Culling, Frustum Culling 등 컬링 기법으로 그리지 않아도 되는 메쉬를 제외시킨다.
  • Level of Details를 적용하여 멀리 있는 메쉬를 단순화하여 그린다.

메쉬 인스턴싱으로 묶어서 그리기

메쉬의 렌더링 비용 자체를 줄일 순 없지만 병목이 심한 CPU <-> GPU 통신량, 즉 드로우 콜의 횟수 자체를 줄이는 방법이다.

머터리얼 인스턴스 적극 활용하기

머터리얼 인스턴스(이하 MI)는 부모 머터리얼의 셰이더 코드를 기반으로 파라미터만 수정하기 때문에 컴파일할 셰이더의 수가 줄어들고, 캐시 효율이 좋아진다. DX12에선 아예 셰이더의 수만큼 PSO를 만들기 때문에 그만큼 PSO를 덜 만들 수 있다.

Note

물론 PSO 자체는 로딩중에 미리 만들어두는 것이므로 PSO의 개수가 많아지는게 런타임 렌더링 비용을 증가시키지는 않지만, 로딩 시간이 길어지며 PSO를 바꿔 끼우는 동작도 여전히 비용을 발생시키므로 적으면 적을 수록 좋다.

또한 머터리얼을 교체하는 작업은 렌더링 파이프라인에서 셰이더와 텍스쳐를 갈아끼우는 매우 무거운 동작이기 때문에 CPU 입장에서도 비용 절감 효과가 크다.

물론 MI를 쓴다고 반드시 이런 효과들이 보장되는 건 아니다. 예컨대, MI에서 오히려 셰이더 퍼뮤테이션을 만들어버리면 역효과가 날 수도 있다.

Shader Permutation

머터리얼 내부의 분기로 인해 만들어지는 셰이더의 바이너리. 예컨대 언리얼 머터리얼 그래프에서 Static Switch를 사용하면 나머지는 같고 해당 분기에서 갈리는 두 개의 서로 다른 셰이더가 생성된다.

메쉬 배칭(머지)

특수한 케이스에선 Merge Actors 또는 Mesh Merge 기능을 사용해 여러 Static Mesh를 하나로 배치하여 드로우 콜을 줄일 수도 있다.
단 메쉬 바운드가 커질 수록 컬링이나 LOD, Level streaming 등에도 영향을 주기 때문에 상황을 잘 고려해야 한다.

무거운 렌더링 작업 피하기

투명 머터리얼은 렌더링 패스에서 정렬을 강제하며 픽셀의 중첩을 허용해야 하기 때문에 오버드로우로 인한 비용이 심하다. 따라서 유리나 반투명 파티클을 남발하는 건 피해야 한다.

기타

  • 가능하다면 그림자 렌더링을 끄기
  • 가능하다면 라이트를 줄이기
  • Dynamic Light는 매우 무거우므로 꼭 필요한 동적 라이트가 아니면 Static Light 사용하기
